# Unconditional EAE routing below 20% TAE-side energy

The user proposed `fraction_below_upper2 < 0.2` as sufficient for EAE-like
routing regardless of signed_delta. This pre-adoption audit evaluated that proposal using
the existing shared continuum loader and energy fractions. The audit preserved
production-v5, source datcon files, training labels, and existing sorter outputs.
The user subsequently approved adoption: production-v6 now uses this condition
through the shared `tae_eae_features.classify_gap_region` function. The
pre-adoption tables and their source hashes remain the historical evidence.

The candidate retains all existing branches:

```python
if fraction_below_upper2 < 0.2:
    gap_region = "eae_like"
elif fraction_below_upper2 > 0.5:
    gap_region = "tae_like"
elif fraction_below_upper2 < 0.4 and signed_delta < -0.1:
    gap_region = "eae_like"
else:
    gap_region = "mixed"
```

The new comparison is strict. At exactly 0.2, the existing signed_delta
condition still applies. Mixed modes remain included on the TAE side.
EAE-like is a frequency-routing result, not a GOOD morphology label.

  under the training data root. Use full precision for both decisions.
- Read saved `all_modes_rules.csv` for the fifteen shots fixed by
  `audits/regression15_v5/shot_summary.csv`, under
  `outputs/regression15_v5_20260907/`, and the twelve shots fixed by
  `audits/pilot12_v5_20260908/shot_summary.csv`, under the requested production
  rules output root. Compare the candidate with each stored gap_region.
  INVALID inputs are excluded from routing comparisons. This is a comparison
  of saved full-precision scalars, not a new shot-sorting run.

  or saved production decisions as provenance. `summary.json` records counts,
  the minimum GOOD training fraction, source roots, and SHA-256 hashes of
  configuration, labels, scalar code, and baseline shot tables.

does not fix erroneous crossings caused by the remaining finite edge rises.
